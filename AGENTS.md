# SignalClassifier project instructions

- Canonical repository: https://github.com/schildtaero/SignalClassifier.git. Preserve remote history and user changes; no force pushes. Commit and push completed verified work when implementing authorized updates here.
- Local Linux/WSL2 application, FastAPI and offline static German UI. Do not silently substitute synthetic data for unavailable SDR hardware.
- CPU works without PyTorch; neural CPU/CUDA is optional. Never label a proposed topology as empirically superior without recorded experiments.
- Preserve original capture groups across replay, clipping, export and import. Split train/validation/test by independent origin group before segmenting or fitting normalization.
- Distinguish provisional frequency hints, confirmed human labels and observed decoder evidence. Preserve actual sample-rate/center-frequency units and provenance. Digital dBFS is not calibrated dBm or absolute SNR.
- Do not claim universal drone RF/video decoding, authenticated Remote ID, hardware accuracy or real-time performance without corresponding tests. Show absent values as unknown.
- Runtime IQ, SQLite, model weights, venvs and credentials stay outside Git. Model imports must remain safe numeric/weights-only loaders and never execute supplied Python.
- Meaningful checks: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 .venv/bin/python -m unittest discover -s tests -v`, `node --check signalclassifier/static/app.js`, `node tests/test_frontend.js`, `bash -n start.sh setup.sh install_driver.sh`. Installer tests must mock privileged/package/network commands; never execute the vendor installer during automated software checks. Physical SDR, Windows/WSL and CUDA acceptance are separate from synthetic software tests.
- Keep quality rankings based on independent validation, with final test values separate. Training-only models have no quality score. Full realtime points begin at 5× speed using CPU p95 timings; imported hardware scores must not be presented as measured on the current laptop. Live comparisons are IQ samples, not continuous inference or measured accuracy without reference labels.
- Automatic optimization must keep test IQ unread until the winner is fixed. Retain trial failures, budgets, structured events and immutable queue-time inputs; report exports must never replace historical labels or hardware with current values.
- Independent training uses bounded persistent spawn workers, with fresh per-job RNG/context and no nested training pools. Respect effective CPU/RAM/GPU limits; pause managed compute for CPU ranking measurements and keep coordination waits separate from active training costs. Missing/stale telemetry is not zero utilization.
- Keep README, version, supported capability documentation and verification notes consistent with the delivered implementation.
- For scientific experiment reports, reuse the user-approved ten-chapter structure in `docs/berichtsvorlage.md` and `docs/berichtsgliederung.json` unless the user explicitly requests another structure. Keep private experiment/report artifacts outside Git.
