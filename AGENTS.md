# SignalClassifier project instructions

- Canonical repository: https://github.com/schildtaero/SignalClassifier.git. Preserve remote history and user changes; no force pushes. Commit and push completed verified work when implementing authorized updates here.
- Local Linux/WSL2 application, FastAPI and offline static German UI. Do not silently substitute synthetic data for unavailable SDR hardware.
- CPU works without PyTorch; neural CPU/CUDA is optional. Never label a proposed topology as empirically superior without recorded experiments.
- Preserve original capture groups across replay, clipping, export and import. By default split train/validation/test by independent session before segmenting or fitting normalization. The explicit allow_same_session checkbox may instead separate original recordings: keep each recording, its derived clips and detected duplicates together, and persist the lack of session independence in results and paper exports.
- Distinguish provisional frequency hints, confirmed human labels and observed decoder evidence. Preserve actual sample-rate/center-frequency units and provenance. Digital dBFS is not calibrated dBm or absolute SNR.
- Do not claim universal drone RF/video decoding, authenticated Remote ID, hardware accuracy or real-time performance without corresponding tests. Show absent values as unknown.
- Runtime IQ, SQLite, model weights, venvs and credentials stay outside Git. Model imports must remain safe numeric/weights-only loaders and never execute supplied Python.
- Meaningful checks: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 .venv/bin/python -m unittest discover -s tests -v`, `node --check signalclassifier/static/app.js`, `node tests/test_frontend.js`, `bash -n start.sh setup.sh install_driver.sh`. Installer tests must mock privileged/package/network commands; never execute the vendor installer during automated software checks. Physical SDR, Windows/WSL and CUDA acceptance are separate from synthetic software tests.
- Keep quality rankings based on independent validation, with final test values separate. Training-only models have no quality score. Full realtime points begin at 5× speed using CPU p95 timings; imported hardware scores must not be presented as measured on the current laptop. Live comparisons are IQ samples, not continuous inference or measured accuracy without reference labels.
- Automatic optimization must keep test IQ unread until the winner is fixed. Retain trial failures, budgets, structured events and immutable queue-time inputs; report exports must never replace historical labels or hardware with current values.
- Independent training uses bounded persistent spawn workers, with fresh per-job RNG/context and no nested training pools. Respect effective CPU/RAM/GPU limits; pause managed compute for CPU ranking measurements and keep coordination waits separate from active training costs. Missing/stale telemetry is not zero utilization.
- Keep README, version, supported capability documentation and verification notes consistent with the delivered implementation.
- For scientific experiment reports, reuse the user-approved ten-chapter structure in `docs/berichtsvorlage.md` and `docs/berichtsgliederung.json` unless the user explicitly requests another structure. Keep private experiment/report artifacts outside Git.
- Write scientific reports for well-educated non-specialists: spell out every technical abbreviation and explain its function at first use; define unfamiliar terms, symbols and units. Executive summaries must stand alone. Follow the audience and writing rules in `docs/berichtsvorlage.md`.
- Multi-signal decisions must retain separate waveform/modulation/protocol/service/emitter levels, immutable sample-window/source context and model/pipeline identities. Closed-set scores and frequency hints never prove an unknown-class rejection, protocol decode or emitter identity.
- Preserve bounded channel/model/history budgets and visible omissions. Scan plans are sequential and hardware-limited; requested dwell and planned coverage never substitute for measured sample evidence or simultaneous reception.
- GitHub paper publication is explicit opt-in per experiment, separate from training success. Use a public field allowlist; never upload the private report bundle, IQ, weights, raw metadata/events, free-text notes, local paths or credentials. Keep validation and test separate and preserve pseudonymized origin groups. Tokens stay in environment variables or an explicitly configured private user file outside the repository; never execute that file or expose its value in UI/logs. No force pushes or default-branch publication.
- With receiver classification disabled, keep energy detection and selected recording but skip all automatic model paths, extra analysis filters and IQ rings. Preserve overflow evidence; a Soapy device overflow does not by itself identify a CPU bottleneck. Explicit reference-button clicks must measure anew, with measurement context.
- Hot status counters must use SQL counts rather than loading archived experiment/model JSON. Large JSON decoding and deallocation can hold Python's GIL long enough to starve the SDR reader even when DSP processing ratios are low.
- Keep the spectrum display stream bounded and latest-only, independent of IQ capture and classification. Copy immutable measurement context briefly under the capture lock; project/encode outside it and never hold capture or hub locks during socket I/O. Preserve FFT timestamps, distinguish status revisions from new measurements, and show gaps rather than inventing continuous RF coverage. Slow or hidden viewers must not backpressure recording.
- Generator planning and startup must not transmit implicitly. Preserve the exclusive receiver lease until reads and cleanup truly finish; serialize start with stop and mute independently of disk faults. SDK-off acknowledgement is not physical RF verification. A host crash may leave cyclic TX active; never auto-resume an interrupted campaign. Manual TX gain is a ceiling and variation only subtracts attenuation.
- Generated-reference labels are distinct from human labels and independently decoded RX classes. Keep actual TX/RX settings, finite waveform hashes, source/transport, payload roots, label facets and complete/partial capture evidence. Constant control waveforms and fixed external demo payloads do not create fresh validation/test cohorts. Generic OFDM/chirps are not WLAN/DVB/LoRa encoders. OnAir mode names require a closed audited CLI registry; never rely on its unknown-ID fallback.
